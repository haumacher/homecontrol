HomeControl

The smart-home controller on a thumb-sized ESP32-C6 board. It runs your KNX installation's schedules, rules and visualization pages, talks to Zigbee devices, and keeps working when your PC, the internet and the cloud are off.

The idea in one sentence

You engineer your home in E-Home (rooms, devices, rules, schedules, pages); E-Home deploys the result to the controller, and the controller executes it on its own, right at home: on the KNX bus over KNXnet/IP and in its own Zigbee network.

1. Engineer

E-Home imports your ETS project and lets you write rules and schedules and design the pages for the wall tablet or the phone.

2. Deploy

E-Home sends a signed runtime image to the controller. Only images signed for your installation are accepted.

3. Run

The controller switches, dims and reports on its own, serves its web pages on your home network, and remembers values and history across restarts.

What you need

  • An ESP32-C6 board with 4 MB flash or more, for instance the Espressif ESP32-C6-DevKitC-1 or -DevKitM-1. The status LED and the button of these devkits are used as they are.
  • A USB cable that carries data (not a charging-only cable).
  • Google Chrome or Microsoft Edge on a desktop computer (Windows, macOS, Linux). Firefox, Safari and phones cannot talk to serial ports.
  • Your WiFi name and key (2.4 GHz; the ESP32-C6 has no 5 GHz radio).
  • For KNX: a KNXnet/IP interface or router in the same network. For Zigbee: nothing, the radio is on the board.

Only the ESP32-C6. The firmware does not run on the classic ESP32 or on the S2, S3, C3 or H2: the installer stops with "Your … board is not supported". Boards with 8 or 16 MB of flash work, but the installer writes the 4 MB layout, so the controller uses 4 MB of it.

Step 1 — Connect the board

Plug the board into your computer. On a devkit with two USB sockets use the one labelled USB (the chip's own USB port), not UART: the WiFi setup after the installation and the console only speak over that port.

Step 2 — Install the firmware

This browser cannot install the firmware. Open this page in Google Chrome or Microsoft Edge on a desktop computer.

Click the button. The browser asks which device the page may use: choose USB JTAG/serial debug unit (Windows may say USB Serial Device (COMn)) and click Connect.

 

The dialog then offers Install HomeControl:

  • A new board (or one that ran other firmware): the next question is Erase device. Tick it for a board that ran something else, so nothing of the old firmware stays behind; for a board fresh from the factory it makes no difference.
  • A board that already runs HomeControl: the dialog says Update HomeControl and does not erase. What survives and what does not is explained under Reinstalling below.

Confirm with Install. Writing takes one to two minutes; do not unplug the board meanwhile.

Step 3 — Join your WiFi

Right after the installation the dialog offers to set up WiFi: pick your network, enter its key, Connect. The status LED blinks fast while the controller connects. When it is online, the dialog offers Visit Device.

Other ways in:

  • WPS: a controller without WiFi credentials waits for WPS (LED blinks fast, about five times a second). Press your router's WPS button; on a FRITZ!Box it is Connect / WPS. To pair again later, hold the board's BOOT button for 3 s.
  • Later from this page: the WiFi setup is offered for 5 minutes after the board starts, and for one minute once it is online. Click the install button again: it restarts the board and offers Configure Wi-Fi.
  • Serial console: wifi set <ssid> <key> at the hc> prompt (any serial terminal on the USB port).

Step 4 — Open the controller

Open http://homecontrol-xxxxxx.local/ in a browser on the same network, where xxxxxx are the last six hex digits of the board's MAC address (the dialog's Visit Device link has the right name). If the name does not resolve, look the device up in your router's list and open its IP address, for instance http://192.168.178.42/.

  1. Set the device password. A new controller shows only this page: the first person to open it chooses the password (8 to 64 characters). Do it right away.
  2. Turn on updates. Settings → Firmware update → Update source: 
    https://haumacher.github.io/homecontrol/stable
    The controller then checks once a day, installs new releases by itself, and downloads the language pack of its release (Settings → Language, e.g. Deutsch). Every update manifest is signed; the controller installs only releases signed with the HomeControl release key it carries.
  3. Connect E-Home. In E-Home, add the controller to your installation; it shows a one-time code. On the controller's Settings page, card E-Home, enter E-Home's address and the code. From then on E-Home deploys to the controller.

The LED tells the state at a glance:

LEDMeaning
fast blinkwaiting for WPS, or connecting with the WiFi setup
slow blink (½ s on, ½ s off)no IP address yet, or reconnecting
short pulse once a secondonline, nothing deployed yet
on, with a short dropout each secondconfigured, but something fails (e.g. the KNX connection is down)
onready

Keep it in your home network. The controller must not be reachable from the internet: no port forwarding, no "exposed host" for it in the router. E-Home reaches it through a connection the controller opens itself.

Reinstalling and updating

An installed controller is best updated over the air (the update source above) or with Settings → Firmware update → Install firmware file, using homecontrol.bin from the releases. Both keep everything.

Installing again from this page writes the whole firmware (bootloader, partition table, updater, application) and an empty storage:

Update (no erase)Erase device ticked
WiFi, device password, remembered logins, E-Home connection and the installation's key, settingskepterased
Zigbee network and its deviceskepterased
Deployed runtime image, last values, history, language packerased (E-Home deploys again)erased

So the page is the way to bring a controller back that no longer starts; Erase device starts it over like a new one.

Troubleshooting

The board does not appear in the browser's list
  • Try another cable (many are charging-only) and the USB socket of the board.
  • Close every other program that holds the port (a serial monitor, the Arduino IDE, a second browser tab with this page).
  • Linux: your user needs access to /dev/ttyACM*: sudo usermod -aG dialout $USER, then log in again (on Arch Linux the group is uucp).
  • Windows and macOS need no driver: the ESP32-C6's USB port is a standard serial device.
"Failed to initialize" or the installation stops right away

The firmware on the board may be crashing so fast that the browser cannot switch it into download mode. Put it there by hand: hold BOOT, press and release RESET, release BOOT, then click the install button again. Afterwards press RESET once: a board in download mode stays there until the button is pressed or the cable is replugged.

The WiFi setup does not appear, or fails

The setup is offered for 5 minutes after the board starts. Click the install button again (it restarts the board) and choose Configure Wi-Fi. "Unable to connect" means a wrong key or a network out of reach; 5 GHz-only networks cannot work. WPS is the fallback (Step 3).

Forgot the device password

Connect a serial terminal to the USB port and enter web password clear at the hc> prompt; the next visit sets a new one.

Install without this page (esptool)

Download the six files of a release and write them at these offsets (4 MB layout):

esptool.py --chip esp32c6 write_flash \
  0x0 bootloader.bin 0x8000 partition-table.bin \
  0x10000 hc_updater.bin 0x100000 homecontrol.bin \
  0x3b0000 ota_data_ota0.bin 0x3b2000 storage.bin

Leave out storage.bin to keep the stored image and values of an installed controller.
